01

Pull, Congressional Bill Tracker

A civic app that tracks every bill in the 119th U.S. Congress and helps people act on them.

My role
Database schema and data pipeline, in a team of 4
Stack
Python, FastAPI, PostgreSQL, Alembic, pytest, GitHub Actions
github.com/NYU-Congressmen/congress-tracker

19,841 / 19,841

bills in our database, matching Congress.gov exactly. Before the fix, every sync quietly lost 90 of them.

  • 26requests to load all summaries (was ~19,700)
  • 0.08 scached bill text diff (0.60 s first time)
  • 14PostgreSQL tables I designed
  • 83passing tests in CI

Problem

Congress.gov has the data, but no bill status, no search across bills, and one shared limit of 5,000 requests an hour.

An app that called it live would run out of requests and still couldn't answer "which bills about AI passed the House?"

Research

I mapped the API's limits and traps before writing any code.

  • At most 250 items per page, with offset paging, and no status field at all
  • "Rule H. Res. 436 passed House." is a procedural vote, not the bill passing. Status matching only trusts the official wording

Approach

Copy the data into our own Postgres on a schedule, and serve everything from there.

  1. Congress.gov API5,000 requests/hour
  2. Synccount-checked, idempotent upserts
  3. PostgreSQLconstraints in the database
  4. FastAPIsearch, filters, diffs
  5. React appnever calls Congress.gov

Each bill's status is worked out from its action history and never moves backwards. Rules like "one review per user per bill" are UNIQUE and CHECK constraints, so a frontend bug can't write bad data.

What went wrong

Every sync reported 19,832 bills saved, but the database had fewer.

No errors, plausible totals. My first two ideas (re-sort, re-read) were disproved by the data. The real cause: the list was sorted by a date-only field, and 2,023 bills shared one date, so offset pages cut the ties differently each time. Newest-first lost 90 bills per run; oldest-first lost 49.

Result

A stable sort plus a check against the API's own count, with a re-read and deduplication if anything is missing.

A test fakes the API and drops an item on purpose to prove the second pass recovers it. Production now matches Congress.gov exactly for bills, summaries, and all 539 current members.

02

AskNYC Zoning Assistant

Ask a plain-English question about NYC zoning; get an answer grounded in the Zoning Resolution, with sections cited.

My role
Solo, end to end
Stack
Python, FAISS, Sentence-Transformers, Llama 3.1 (Ollama), Streamlit, Docker
github.com/ekberby/AskNYC

Every claim, cited

The model may only answer from the retrieved zoning text, and must name the section behind each claim.

  • Top 3section-tagged passages per question
  • ~3,000characters per passage
  • 1command to run, fully local

Problem

Zoning rules are dense, and a chatbot that guesses is worse than none.

On a regulatory topic, an answer is only useful if you can check where it came from.

Approach

Retrieve first, then generate only from what was retrieved.

  1. Questionplain English
  2. Embedall-MiniLM-L6-v2
  3. FAISS searchtop 3 passages
  4. Llama 3.1answer only from passages
  5. JSONanswer + sources

Key decisions

Keep every passage traceable to a section, and keep everything on the machine.

  • Passages keep their section number, title, and link, with a small overlap so context isn't cut at a boundary
  • Normalized vectors in an inner-product index make retrieval a plain cosine-similarity search
  • A local model through Ollama means no API costs or keys, packaged in Docker

Honest status

It works end to end; it has not been benchmarked yet.

The next step is a small set of zoning questions with known answers, to measure how often the cited section is the right one.

03

Satellite Land-Use Classification

Sorting Sentinel-2 satellite tiles into 10 land-use types, for planning and environmental monitoring.

My role
Solo
Stack
Python, PyTorch, ResNet18, Google Colab
github.com/ekberby/Deep-Learning-Land-Use

92.6%

test accuracy on the EuroSAT dataset (27,000 images, 10 classes).

This model92.6%
Random chance10%

Approach

Reuse what a model already knows about images, and train only the last layer.

A ResNet18 pretrained on ImageNet, with the backbone frozen and a new 10-class head. It passed 90% accuracy within a single epoch.

What it gets wrong

Crops vs. other vegetation, and highways vs. rivers.

From orbit these share texture and color, so the confusion comes from the images themselves. Visually distinct classes do far better: forest and sea/lake reach 97–99% precision.

04

NYC Bus Speed Prediction

Predicting bus speeds and severe delays, and ranking which routes should get camera enforcement of bus lanes next.

My role
Data integration, regression and classification models, clustering and route ranking, in a team of 4
Stack
Python, pandas, scikit-learn
Code
Course project, no public repository

R² 0.704

predicting bus speed with a random forest, and ROC-AUC 0.900 for flagging severe delays.

Random forest0.704
Linear baseline0.435

Problem

NYC buses are slow, and bus-lane cameras cover only some routes. Which ones should be next?

Research

5 transit datasets merged into one 6.14M-row table.

Segment speeds, wait times, 4.76M camera violations, enforced routes, and hourly ridership, joined with no missing values.

What didn't work, and the fixes

Three traps that would have made the results look better than they were.

  • Random split: bus speed is seasonal, so a random split lets the model see the future. We split by time instead
  • Linear models: plateaued at R² 0.435 because hour-of-day and distance effects aren't linear. Random forests closed the gap
  • Naive comparison: enforced routes look slower (8.07 vs 9.33 mph) only because cameras went to slow routes first. We compared each route with itself, before and after

Result

A ranked shortlist for the next round of enforcement.

  • +6.42%average speed on enforced routes after cameras
  • 7routes in the top 10 under every weighting
  • 0.0007std. dev. of R² across 10 random seeds

The busiest corridors are already about 95% enforced; the remaining demand is in Queens and Brooklyn.
